# 自然な日本語の記述

AI特有の文章スタイルを排除し、簡潔で読みやすい日本語テキストを生成・レビューする。

## クイックスタート

1. 文書の種類と対象読者を指定する
2. 文体を指定する：`です・ます調` または `だ・である調`
3. テーマ・アウトライン・既存の下書きを提供する
4. テキストを生成または修正する

## 整形

- 一文ごとに改行し、段落の区切りは空行で示す。
- 見出しは一つの自然な句にする。ダッシュや罫線で「種別──主題」のように二要素を詰め込まない。
- コード・コマンド・設定値はインラインコード（`` `値` ``）で示す。複数行はコードブロックで囲む。
- 用語を初めて定義・導入するときは**太字**にする。以後の言及・引用・通称には「」を使う。
- 用語とその説明を箇条書きで並べるときは全角コロンで区切る（例：`**用語**：説明`）。
- 本筋から外れる補足は脚注（`[^ラベル]`）に降ろす。
- ダッシュ（`—` `―` `——`）を日本語の地の文で使わない。補足の挿入は括弧（）に、言い換えは読点か句点で処理する。
- 中黒（`・`）を日本語の並列に使わない。読点または箇条書きに置き換える。固有名詞の内部は除く。

## 文体の選択

呼び出し時に文体が指定された場合は必ずそれに従う。指定がない場合は文書の種類から推定する。

| 文書の種類 | デフォルトの文体 |
|---|---|
| 対外レポート・クライアント向け文書 | `です・ます調` |
| 社内技術レポート・調査文書 | `だ・である調` |

## 記述ルール

**文の長さ**
- 意味を持たない語は省く。
- 長い文章になる場合は、適切な読点・句点を織り交ぜ、改行して読みやすさを確保する。

**語彙**
- 格式張った表現より平易な言葉を優先する。
  - ✗ `鑑みると` → ✓ `考えると`
  - ✗ `実施する` → ✓ `行う`
- 指す対象は具体的な語で書く。「AI」「ツール」「システム」のような広い語でぼかさない。

**助詞**
- `は`・`が`・`を`・`に` などの助詞は必ず記述する。簡潔さのために省略しない。

**略語**
- 括弧書きで正式名称を補足しない。略語をそのまま使用する。
  - ✗ `AWS（Amazon Web Services）` → ✓ `AWS`

## 段落構成

- 一段落に一つのトピックを置く。段落の最初の文を読めば何の話かわかるように書く。
- 同じ主張を言い換えて繰り返さない。一つの主張は一度だけ書く。
- 前の段落との関係は接続表現で示す（`しかし` `実際` `そのため` など）。
  内容を持たない `また` `さらに` の連打とは区別する。

## 排除すべきパターン

### 冗長・水増し

| パターン | 例 | 修正方法 |
|---|---|---|
| 冗長な言い回し | `〜という点において` | `〜において` に短縮、または文を再構成する |
| 水増し表現 | `〜することができます` | `〜できます` に置き換える |
| 接続詞の連打 | `また、` `さらに、` `なお、` の多用 | 意味上必要な場合のみ使用する |
| 内容の繰り返し | 段落の冒頭と末尾で同じ内容を述べる | 一度だけ記述する |
| 過剰な箇条書き | 散文で自然に読める内容をリスト化する | 散文で記述する |

### LLM 特有パターン

AI が生成する文章に頻出する型。書いたら点検する。

| カテゴリ | 避けるべき表現 | 指針 |
|---|---|---|
| 予告・総括 | `重要なのは〜である` `まとめると` `〜に他ならない` | 主張はそのまま書く。前置きで予告しない |
| 空虚な形容 | `不可欠` `核心的` `多角的` `包括的` | 中身で示す。強調だけの形容詞を置かない |
| 空虚な動詞 | `掘り下げる` `言語化する` `触れる` | 何をどう書いたかを具体的に示す |
| 根拠なき強調 | `非常に` `極めて` `大いに` | 削る。必要なら事実で示す |
| 根拠なき弱化 | `〜と言えるだろう` `〜かもしれない` | 確信があれば言い切る。不確実なら根拠を添える |

## 演出の抑制

- 太字は誤読を防ぐ箇所や論理の要所に絞る。装飾目的で多用しない。
- 短い一文を独立した段落にして緊張を演出しない。
- `重要なのは〜である` のような前置きで主張を予告しない。主張をそのまま書く。
- `AではなくBだ` という対句の決め台詞を多用しない。

## 図解

- 図解にアスキーアートを使用しない。
- すべての図解にMermaidを使用する。ダイアグラムの種類はユーザーの指示に従う。
- 種類の指定がない場合は、内容から最適なMermaidのダイアグラムタイプを推定する。

## 注意事項

- 既存のテキストを修正する場合、元の意味を保持する。新しい情報を追加しない
