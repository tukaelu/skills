# 記事の執筆

依存関係と物語の分析で記事の構造をマッピングし、明確さとフローを高めるためにセクションごとに書き直す。

## クイックスタート

1. 記事を共有する（テキストを貼り付けるかファイルパスを提供する）
2. 想定読者とゴールを指定する（または推定させる）
3. スキルがセクションマップを提案する。確認または調整する
4. セクションを 1 つずつ書き直し、それぞれ承認を取る
5. 最後に総合的なレビューを提供する

## ステップ 1: 記事を理解する

記事全体を読み、明らかでない場合はコンテキストを確認する:
- [ ] 想定読者は誰か？
- [ ] 読んだ後に何を*考え、感じ、行動する*べきか？
- [ ] 制約はあるか（トーン、文字数、スタイルガイドなど）？

## ステップ 2: 構造分析

記事を**情報依存グラフ（DAG）**としてモデル化する。一部の概念は他の概念よりも先に
確立されている必要がある。

各セクションについて、そのセクションが伝えるべき**核心メッセージ**を 1 文で書く。

次の評価をする:
- [ ] 現在の順序は情報の依存関係を尊重しているか？
- [ ] 物語の緊張はどこで高まり、どこで解放されるか？（問題 → 共感 → 解決策 → 行動）
- [ ] 冗長、孤立、欠落しているセクションはないか？

提案する構造を提示する:

```
セクションマップ:
① イントロ — フック + 問題提起
② 背景 — 「X」を定義する  [③ と ④ の前提]
③ 現状 — 何が壊れているか  [② に依存]
④ 解決策 — アプローチ  [③ に依存]
⑤ まとめ — 行動への呼びかけ  [すべてに依存]
```

並べ替えを提案する場合は、依存関係の理由を説明する:
> 「セクション B はセクション C の前に置く必要があります。C はすでに読者が X を知っていることを前提としているためです。」

**続行前にユーザーの確認を待つ。**

## ステップ 3: セクションの書き直し

確認された各セクションを以下のルールに従って書き直す:

**段落のルール**
- 1 段落につき 1 つのアイデア（冒頭の文で述べる）
- 1 段落の最大文字数は 240 字（超える場合は分割する）
- デフォルトは能動態；行為者よりも行為が重要な場合のみ受動態を使う
- 「このセクションでは〜について説明します」のような前置きを削る

**つなぎのルール**
- 各セクションの末尾は、話を締めるか次につなげる文で終わる
- 最初以外の各セクションは、直前のセクションとつながる文で始める

**認知負荷チェック**: 書き直し後、以下に当てはまる段落にフラグを立てる:
- 2 つ以上の新しい用語を導入している
- 記事でまだ説明されていない知識を前提としている

書き直したセクションを表示し、次のセクションへ進む前に承認を取る。

## ステップ 4: 最終レビュー

すべてのセクションが承認されたら、全体を通して確認する:
- [ ] 冒頭の文は読み続けたいという引力を生み出しているか？
- [ ] 各セクションの核心メッセージは明確に伝わっているか？
- [ ] 結末はイントロで示した約束を果たしているか？

主な変更点を簡単に補足して最終版の記事を提供する。

---

## 注意事項

- スキルを呼び出したときにユーザーが使用した言語で常に応答する
- 記事がファイルにある場合は Read で読み込む。そうでない場合はユーザーに貼り付けを求める
- セクションを黙ってスキップしない。変更が不要なセクションも簡単に確認を伝える
